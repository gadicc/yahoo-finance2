# Development

Use exact Bun 1.4.3 for development and root package management. Node 24.21.0
is the auxiliary tool host. Select local binaries on PATH; do not replace global
tools. Target pull requests at `dev`.

```sh
bun --version
bun run check:toolchain
bun install --frozen-lockfile
```

Run the explicit toolchain check before resolution. `.bun-version` and
`packageManager` must agree, and `bun.lock` must exist. The normal preinstall
hook repeats the guard. Frozen mode alone does not reject a missing lockfile;
do not bypass lifecycle hooks. Review `bun pm untrusted` when changing the graph.

The root manifest is private, with exact dependency pins. `bun.lock` alone owns
root JavaScript dependencies. `tests/cloudflare/package-lock.json` belongs to
the separate npm 10.9.9 Workers graph; never install that harness with Bun.
`deno.json` retains package identity/version, all 28 public export keys and
minimal production mappings. It has no development tasks or permissions. The
isolated publisher owns its own auxiliary lock; there is no root Deno lock.

Consumers require Node >=22.0.0, Bun >=1.4.3 or Deno >=2.0.0. JSR distribution
remains supported. A Deno binary may run only inside the dedicated isolated
publisher, including its explicitly selected nonpublishing consumer rehearsal.
See [platforms](platforms.md) and [release guidance](RELEASING.md).

## Types, schemas and style

```sh
bun run typecheck
bun run typecheck:incremental
bun run typecheck:negative
bun run schema:check
bun run format:check
bun run lint
bun run docs:lint
```

The maintained checker uses root-pinned TypeScript and separate strict library
and tools projects. Library roots include production `src/` and both `bin/`
entrypoints; every public export must be covered. Tools include scripts,
JavaScript with semantic checking, tests, helpers and subprocess entrypoints.
Workers use their own type gate. `bun scripts/typecheck.ts --list` reports actual
roots and exclusions. Node/DOM ambient types preserve the standard fetch
contract; Bun/Deno ambient globals are not exposed to production code.

Normal checking writes no output. Incremental checking owns only recognized
build-info files under ignored `.migration-results/typecheck-v1/`; unexpected,
linked or unowned cache contents fail without adoption or automatic deletion.
Negative controls use disposable projects and must detect actual type errors.
Compiler diagnostics and invalid strict configuration fail the check.

Interfaces marked `@yf-schema` own runtime validation. After an interface change,
run `bun run schema` or select explicit module paths. Every run compiles current
imported types; `--force` remains accepted for compatibility. Include consumers
of shared types when selecting roots. `schema:check` compares generated bytes
without writing. Empty inventories and orphan outputs fail. The schema generator
retains its private TypeScript 5.9 compiler, separate from project TypeScript 6.
Generation compiles all selected roots before writing, stages changes privately
and preserves the whole batch on compile/generation failure. Individual replacement
is atomic, but a later filesystem failure can leave earlier outputs changed. Known
missing/malformed generated JSON imports use an in-memory repair overlay, never
on-disk placeholders. Watch with `bun run schema --watch`; restart after editing
generator code.

Biome formats maintained JS/TS/JSON/JSONC with the repository configuration.
`bun run format` changes layout; lint does not apply fixes. Keep recommended
rules, visible warnings and precise, explained suppressions. Never apply unsafe
fixes unattended. Markdown and YAML require manual review. Dependencies,
fixtures, generated output, plans and locks keep their own ownership rules.

Use VSCode's built-in TypeScript extension with the workspace version and the
recommended Biome extension. Workspace Deno is disabled. Keep explicit `.ts`
local imports. Save-time fix-all/import organization stays disabled. The schema
watch task can start on folder open after workspace trust and automatic-task
permission; Bun must be available to the editor process.

## API documentation

```sh
bun run docs:gen
bun run docs:lint
bun run docs:watch
bun run docs:open
```

TypeDoc uses the installed root graph. Generation writes owned `jsdocs/`;
lint renders to temporary output and publishes nothing. Watch polls the actual
source/configuration/tool closure, preserves last successful output and recovers
after invalid inputs are repaired. Open explicitly invokes the platform opener;
it neither generates docs nor checks remote links. The prose docs tree is not
included in the generated API site.

Every public export must have a reflection and HTML page. Reports record actual
tool/compiler versions, export/link coverage, input inventory and provenance.
Source links require exact Git commit-byte agreement; dirty source, archives and
unknown origins retain positions without invented links. Supported config extends
must be explicit local JSON/JSONC paths with matching Node/TypeScript resolution.
Restart watch after dependency installation changes.

New or increased documentation diagnostics fail. Existing debt is a reviewed
multiset, with parser compatibility exceptions tracked separately. Do not refresh
baselines automatically or invent field semantics. Unknown bootstrap options and
startup warnings/errors remain fatal. Schema repair uses this same gate.

Custom docs output must be new/empty or carry the exact docs ownership marker;
only `jsdocs/` is allowed inside the checkout. Linked/foreign targets fail. A lock
serializes writers and staging preserves prior output on conversion failure.
After a crash, inspect stale locks before manual recovery. A failed replacement
and failed rollback retain the previous output under `OUTPUT.lock/previous`.

See [testing](testing.md), [fixture capture](fixture-capture.md),
[packaging](packaging.md), and [CONTRIBUTING](../CONTRIBUTING.md) for the remaining
workflow. Use scoped Conventional Commits with motivation and the required
[agent footer](../AGENTS.md#commit-messages). Adding a module also requires its
exports, schemas, cached/synthetic tests and factual API documentation.
