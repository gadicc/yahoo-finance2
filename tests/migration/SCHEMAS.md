# Schema tooling migration (E04–E05; E06 command evidence)

`bun run schema` regenerates the schemas for `@yf-schema` source files under
`src/`. `bun run schema src/modules/quote.ts src/modules/options.ts` selects
explicit roots. `bun run schema --watch` watches source/config changes; it also
accepts explicit roots. `bun run schema:check` regenerates entirely in memory,
compares exact serialized bytes, and exits 1 for stale, missing or invalid
outputs without creating, modifying or deleting files. Usage errors exit 2;
other failures exit 1; help and successful non-watch commands exit 0.

The generator uses Node filesystem/path/watch APIs and the root-installed
`ts-json-schema-generator` 2.9.0, including that generator's bundled TypeScript
5.9.3 compiler. The independent project typecheck remains TypeScript 6.0.3. The
schema compiler explicitly selects Node ambient types; it does not inherit
stale/native Bun fetch extensions. The existing custom function formatter is
preserved: callback definitions remain `{}` and literal option discrimination
and reference pruning retain their existing tests.

No Deno process, cache inspection, lock inspection or package symlink mutation
is used. All 13 schema structures and property ordering match the prior
committed outputs byte-for-byte after removing the `$comment` line. The sole
output change advertises `bun run schema` and removes the unimplemented claim
that VSCode runs generation automatically. `scripts/schema-tsconfig.json`
continues to support JSON imports and local `.ts` extensions.

Default, explicit and `--force` runs always compile current imported types. The
old source/output mtime shortcut is deliberately removed: a shared type can
change without touching any dependent module. `--force` remains accepted for
command compatibility. Unchanged generated bytes are not rewritten, so unchanged
outputs retain their timestamps. Invalid flags fail before scanning;
`--check --watch` is rejected. Empty default inventories and orphan
`.schema.json` outputs fail with guidance to restore the marked source or remove
the obsolete output; the CLI never deletes orphans automatically.

Missing or malformed **known generated** JSON imports get an in-memory `{}`
compiler-host overlay, avoiding the old on-disk placeholders and allowing
repair. Existing valid generated JSON and ordinary JSON imports are loaded and
checked normally. All TypeScript diagnostics and custom generation failures
remain fatal. Every selected root compiles before any write. Changed outputs are
staged in sibling temporary files and renamed over their targets, with temporary
files cleaned on failure. A compile/generation failure leaves the whole batch
untouched. Filesystem failures during the rename phase may leave earlier targets
updated; each individual output replacement is atomic.

Watch opens before its initial scan, debounces bursts, and serializes runs.
Edits arriving during an asynchronous run request a later run. Source/type
additions, removals and config changes trigger full regeneration of the chosen
roots; generated output writes, dependencies, fixtures and caches are ignored.
Errors are reported while watching continues, so a repaired source can recover.
Watcher failures close the watchers and set a nonzero status. SIGINT/SIGTERM
cancel pending timers, close watchers and remove signal listeners. The real
watch subprocess and shutdown were verified on Linux with Bun 1.4.3; other
platforms remain H05. Restart watch after editing the generator's own executable
code or custom formatter implementation.

The focused regression suite uses temporary synthetic projects for flags,
read-only checks, shared imports with deliberately old timestamps, invalid
inputs, failure preservation, missing generated JSON, ordinary JSON errors,
subprocess exit codes, scheduler recovery, empty inventories and orphan outputs.
It also checks every real schema byte and runs a real watch subprocess across an
imported-type edit and SIGTERM shutdown.

[Evidence](results/e04-e05-schema.json) records clean-install and isolated
verification. A disposable checkout changes `quote.ts` only for a negative
control: the no-write check detects both quote and dependent options schemas,
even with the input mtime forced to the epoch; regeneration repairs them and the
check passes. Historical/chart consumer tests also pass. All 1,201 HTTP fixture
contents and `bun.lock` remain unchanged.

At the original E04/E05 snapshot, E06 routing and the Deno metadata cleanup
were still pending. The maintained Tests workflow now runs `bun run schema:check`
as its no-write gate; the [CI policy](CI.md) and [repair policy](CI-REPAIR.md)
record stale/shared-import routing and independent repair controls. Ordinary
schema/test/checker commands use the root Bun/TypeScript graph; retained source
publication metadata has no development Deno tasks or permissions.
